# Resolve tie measurement

Retired in the (c) M5 change: render version 3 no longer stores f16 between
color-adjust stages or resolves through rgba8unorm (Q14 in rgba16uint, then
`div_q(q * 255, 16384)` bytes in rgba8uint), so there is no unorm tie left to
measure. The parity runs stop emitting these files; the CI summary steps skip
them when absent. The description below is kept for the earlier artifacts.

`tie-8192.json` and `tie-8192.md` accompany the alpha-measure artifacts.
These diagnostics never supply parity assertions or expected counts.
Native Metal/lavapipe and browser SwiftShader collect each row after tile
readback, before comparing the existing CPU and GPU bytes. Reports survive
pixel mismatches; rendering/readback errors retain their existing behavior.

Q14 values come from a CPU replay, not GPU intermediate readback. The replay
includes mode-0 Q14 premultiplication, the input f16 store, the clear normal
blend, integer color adjustment, and the output f16 store. The clear blend
preserves these input values. Resolve textureLoad reads that f16 value and
textureStore writes it directly to rgba8unorm. All values on this path are
exact multiples of 1/16384 after the output store.

- `resolveInput`: pixels with any tie and channel counts in RGBA order,
  testing `255*q mod 16384 == 8192` immediately before the unorm8 store.
- `adjustOutput8192`: the previous pre-f16 RGB count, retained separately.
- `old8192ResolveHistogram`: resolve Q14 values of those old RGB occurrences,
  with occurrence counts, whether they remain 8192, and whether they are ties.
- `ties`: every resolve tie, with case, coordinates, channel, replayed Q14,
  actual GPU readback byte, CPU reference byte, GPU up/down/other classification
  relative to the two neighboring bytes, and GPU byte even/odd classification.
- `totals`: channel occurrences reached, equal, different, or unavailable.
  Missing bytes are null and classified unavailable, never fabricated.
- `lossyStep2_4_8`: retained precision-loss counts for input RGBA and output RGB
  f16 store calls; alpha passthrough is excluded from the output calls.

Backend identity labels the readback source. `qSource` describes CPU replay;
`byteSource` describes GPU tile readback. Synthetic local smoke-check bytes
are reporting validation only and are not backend measurements.
