# 文書の所有と復旧記録の破棄：修正と検証（2026-10-25）

## 対象

`35be75a` を土台に、組み込み API の次の 2 件を修正した。Rust と WASM のプロトコル番号は変えていない。SDK と同梱 Worker の間に文書の世代を追加した。

- 文書切り替え中に予約した旧ハンドルの操作が、新文書へ適用される。
- `recovery.discard()` が、編集中の文書の復旧記録も消せる。

## 修正

- 文書の作成、ファイル・フォルダの読み込み、復旧、破棄を、編集と同じキューで処理する。旧文書で開始したストロークは、Worker の文書を切り替える前に確定する。
- 編集はキューの実行時にも閉じたハンドルを検査する。読み取り・編集・ストローク入力にはハンドルの世代を付け、Worker も実行時に検査する。別経路で返す `durable` も対象にした。
- Worker を再起動しても、同じハンドルの世代を引き継ぐ。文書を入れ替えると世代を変える。
- 復旧待ちのときだけ破棄を許可する。SDK と Worker の両方で検査し、対象がなければ `CONFLICT` / `no-recovery` で拒否する。復元の後に予約した破棄も拒否する。
- 公開 API の一覧、組み込み手引き、配布用 SDK を更新した。

## 再現と回帰テスト

追加した旧ハンドルのテストが、修正前の配布 SDK で `the queued selection on the old handle succeeded` と失敗することを確認した。修正後は成功する。

組み込みテストに次の 6 件を追加した。

1. 変更通知から文書を新規作成し、その直後に旧ハンドルへ予約した選択が拒否され、新文書を選択しない。
2. 作業中の破棄を SDK と Worker の両方が拒否し、確定済みの記録と再起動後の文書を保つ。
3. ファイル・フォルダを開く場合も、旧ハンドルの予約操作が新文書を変更しない。
4. 古い世代の編集・読み取り・`durable` を Worker が拒否する。現在の世代は再起動後も使える。
5. 描画中に文書を切り替えると、ストロークが旧文書に確定し、新文書の履歴には入らない。
6. 復旧と破棄を同時に呼んでも、復旧後の記録が残り、もう一度再起動できる。
