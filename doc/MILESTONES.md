## M7の実装

- **データモデル**：`TextContent`（本文、基本スタイル、範囲スタイル、枠、組み方向、揃え、縦中横）。オフセットはJavaScriptの文字列添字と同じUTF-16で、サロゲートペアの途中は拒否します。`SetText` は検証・逆Op・Undo・ジャーナル・保存に対応。文書のFontアセットに無いフォントを参照する編集、使用中のフォントの削除は原子的に拒否します。
- **フォント**：OTF/TTF/TTCを文書埋め込みアセット（内容ハッシュ）として保存します。読み込み時にOS/2 fsTypeを確認し、埋め込み禁止・閲覧印刷のみ・サブセット禁止を警告します。ブラウザのシステムフォント（Local Font Access API）は使いません。
- **シェーピング**：rustybuzz 0.20（HarfBuzzのRust移植）。`features` でpalt・liga・kern・fwid等を指定し、spanで部分適用できます。言語タグでlocl。アウトラインはrustybuzzが内包するttf-parserで読みます（設計書のskrifaの代わりに、パーサーを1つにしてWASMサイズを抑えました）。
- **組版（自前）**：段落→書記素→ラン（スタイル・フォント・bidiレベル・縦組みの向き・縦中横）。UAX #14の改行位置に行頭/行末禁則（句読点・閉じ括弧・小書き仮名・長音・踊り字・開き括弧）を加えた追い出し。横組みはUAX #9で行ごとに視覚順へ並べ替えます。揃えは先頭/中央/末尾/均等（段落最終行は先頭）。
- **縦組み**：UAX #50相当の向き分類。漢字・仮名はTTBでシェーピングし、vert/vrt2で句読点・括弧・長音を縦組み字形に、vmtx/VORGで字面を列に配置します。vertの無いフォントでは句読点を右上へ、小書き仮名を右上寄りへ移し、括弧・長音は回転する代替配置（Noto Sans JPの縦組み字形との差を15/100em以内で検証）。欧文・3桁以上の半角数字は90°回転し、ベースラインを列の中心へ置きます。縦中横は自動（既定2桁以下の半角数字）と範囲指定で、全体を1emに収め、はみ出す場合は横方向に圧縮します。
- **描画**：グリフはフォントサイズごとのラン（`TextRun`）にまとめ、表示レベルごとに画面上のem（出力px）で経路を選びます。24px以上はアウトライン（CFFの三次・TrueTypeの二次曲線）を `StyledPath` にしてM6のlyon／4x MSAA経路で、24px未満はサイズ帯ごとのグリフアトラスで描きます。アトラスはグリフを表示倍率そのままで面積被覆（CPUの符号付き面積の累積）としてR8の1024²テクスチャへラスタライズし、出力画素へ1:1で複写します。キーはフォント×グリフ×「フォント単位→出力pxの行列を1/4px/em刻みにしたサイズ帯」（回転・縦中横の圧縮・長体を含む）×原点の1/4pxの位相です。棚詰めで割り当て、最も古く使われた棚ごと追い出します（描画中のコマンドが参照する現在のフレームの棚は追い出さない）。収まらないグリフ（96px超・空きなし）はその1字だけベクター経路へ回します。表示レベルは別々にキャッシュされ、拡大で閾値を超えるとそのレベルはベクター経路で描くため、拡大表示でビットマップが引き伸ばされることはありません。アトラスは派生キャッシュで、デバイス喪失後は場面が持つアウトラインから描き直します。マスク・クリップ・ぼかし・合成もそのまま使えます。組版結果は内容とフォントのハッシュで、アウトラインはフォント×グリフでキャッシュします。どのフォントにも無い文字は位置を保ったまま仮の枠で表示し、未表示文字としてSDKへ返します。
- **選択**：ヒットテスト、キャレット、選択矩形、書記素/単語/行/行頭行末の移動。レイヤー変形を通した文書座標で返します。Playgroundの「テキスト」ツールでドラッグ選択、入力・IME確定・削除・矢印移動、選択範囲への書式・縦中横の適用ができます。選択範囲を上書きした文字は、置き換えた文字の書式を引き継ぎます。

## M8の基礎実装（初期実装の記録）

以下はM8時点の線形履歴の記録です。ブランチ・二親マージ・GCの現行仕様は[設計書](design/VERSIONING-AND-IMAGE-EDITING.md)を参照してください。

- **コミット**：`Commit { parents, snapshot, message, intents, created_at, author }` を整形済みJSONの正規形で保存し、そのBLAKE3をIDにします。Intentは前回コミット以降のTransactionを「意図×対象ノード」で集計し、Undoで打ち消した編集は除きます。変更の無いコミットは拒否します。
- **意味的差分**：NodeIdで木を照合し、追加・削除（部分木の頂点のみ）・移動（親の変更、または兄弟の最長共通部分列から外れたもの）・属性（フィールド名）・画素（タイルハッシュの比較のみ。レイヤー座標と文書座標の範囲）・内容（ベクター命令数、テキストの抜粋・縦横・書式・縦中横）・アセット・選択範囲を返します。画素は読みません。
- **復元**：任意の版を、現在の文書からその版への可逆Op列（1回のUndoで戻せるTransaction）として適用します。履歴は書き換えません。
- **保存**：スナップショットJSONを整形・木の順序の正規形に変え、gitの行差分に向く形にしました。`.alto` とフォルダ形式は同じエントリ（manifest / snapshots / commits / objects）を共有し、manifestに `head` を追加しました。版が参照するタイル・アセットはGCの根として保持し、保存にも含めます。コミットはジャーナルの対象外のため、コミット直後にチェックポイントを取ります（当時の記録。現在の履歴状態遷移はジャーナルにも記録し、受け付ける形式はformat 5 / manifest 2 / commit 2 / render v3のみです）。
- **フォルダ形式**：`objects/`・`snapshots/`・`commits/` は存在しなければ書き、既存は書き換えません。`document.json`（現在のスナップショットの読みやすい写し）と `.gitattributes` を書き、最後に `manifest.json` を置き換えて読み返します。保存の基準にしたmanifestのSHA-256が現在値と違えば、何も書かずにCONFLICTを返します。SDKは `ObjectStorageProvider` として File System Access のフォルダ、OPFS、メモリを同梱します。読み込みはmanifest・スナップショット・コミットから到達するオブジェクトだけを読みます。
- **Git Adapter（`alto-git`）**：エンジンにリンクしない別crateのCLI（設計書の候補のgitoxideではなく、gitコマンドのplumbingを使用）。`sync` は未反映のAltoコミットを古い順に `git fast-import` で1対1のgitコミットへ写します。ツリーはその版の時点のフォルダ、メッセージはIntent要約とレイヤー単位の変更、トレーラ `Alto-Commit` で対応を記録します。オブジェクトは追加だけなので、後のコミットは新しいblobだけを含みます。`diff` / `log` は `.alto`・フォルダ・`<rev>:<folder>` を比較し、`install` で `document.json` のtextconvを登録すると通常の `git diff` もレイヤー見出し付きで読めます。`export` / `pack` で単一ファイルとフォルダを相互変換します。

## M6の実装

- `alto-vector` に型付きスキーマ（Move/Line/Quad/Cubic/Close、塗り規則、RGBA、線幅、線端、結合）を追加。パスはf64で正本を保存します。SVGの円弧・相対命令はkurboで正規化します。
- `SetVector`、`SetVectorMask`、`SetClipPath` は検証・逆Op・Transaction・Undo/Redo・ジャーナル・`.alto`保存に対応。不正な座標やスタイルは原子的に拒否します。
- lyon 1.0.22のメッシュをGPUで4x MSAAのR8へ描き、カバレッジからpremultiplied RGBAへ合成します。線の自己交差でも一本の線の不透明度を重複加算しません。
- メッシュは内容ハッシュと許容誤差のレベル帯でキャッシュ。変形の最大拡大率を上から評価して誤差を決め、ビューの表示タイルはM6文書でL=-6〜12を使用します。ラスターのみの文書は従来経路を維持します。
- ベクターマスクとクリッピングパスはラスター・ベクター・グループ・調整へ適用でき、R8マスクとも積算します。形と固有の変換を編集データとして保持します。
- 拡大時のGaussianは文書に固定した粗いグリッドへ必要領域を要求し、縦横の計算後に補間します。選択の外側は元の解像度を保持し、調整レイヤーのぼかしも下位内容へROIを逆伝播します。フェザーもタイルごとに位相がずれないよう同じグリッドを使用します。
- `VectorRasterizer` は準備結果の関連型を持つtrait。lyonのメッシュと、比較用velloのScene準備で同じ型付きパスを利用しています。本体のGPU描画はlyonです。velloへの本体描画切替は未公開です。
- vello 0.11.0は別WASMの比較ページで実行し、速度・初回描画・AA差を記録。比較結果は [VECTOR-COMPARISON.md](verification/VECTOR-COMPARISON.md) を参照してください。

## M5の実装

- 選択範囲は文書座標のR8タイル。長方形・楕円・投げ縄、追加・削除・共通部分・反転・解除、境界のぼかしに対応します。投げ縄は走査線で判定し、複雑さに上限を設けます。
- マスクはノードのプロパティです。enabled、linked、独立したAffine2を保持します。連動/解除で外観が飛ばず、連動時はノードの変形に追従します。マスク用GPUブラシはグレースケールを描き、終了時にR8の正本へ確定します。
- クリッピングチェーンは基底の色・アルファを分離してから合成し、半透明の基底のアルファを増やしません。
- 調整レイヤーは所属グループ内の下位内容が入力です。明るさ・コントラスト・彩度、Gaussianぼかしを実装。調整マスク、不透明度、Normal/Multiply/Screenも適用します。
- エフェクトは順序付きの非破壊スタック。選択付き効果は、その時点の選択をノード座標のR8マスクとして取り込みます。選択やマスクのオブジェクトは保存・履歴・GC・ジャーナルの参照追跡に含めます。
- M5描画はROIを逆伝播して必要な周辺画素を確保し、RGBA16F中間テクスチャにGPU処理します。Gaussianは縦横2パス。グループの下位内容をぼかす調整にもハローを用意し、最終表示をRGBA8へ解決します。
- 一時ターゲットはGPUキュー順序に従ってプール再利用し、予算を超える場合は明示的なエラーを返します。M5機能を使わない文書は従来の合成経路を使用します。

## 上限・継続課題

以下は現行実装の上限です。[IMAGE-EDITING.md](design/IMAGE-EDITING.md) は2026-10-20時点の過去の設計です。形式番号と版管理の記述は現状と異なるため、現行仕様は [VERSIONING-AND-IMAGE-EDITING.md](design/VERSIONING-AND-IMAGE-EDITING.md) を優先します。

1. sRGB/RGBA8とR8。効果はGaussianぼかし、明るさ・コントラスト・彩度、レベル補正、トーンカーブ、色相・彩度、反転です。シャープ、移動ぼかし、ノイズ、ハイパス、ドロップシャドウ、境界線は未実装です。
2. Gaussianの打ち切り半径・選択のぼかし幅は0〜64文書px、効果はノード当たり32個まで。半径の単位はレイヤー変形後の文書座標です。
3. 選択/マスク生成は最大4096タイル、投げ縄は3〜8192点で処理量にも上限があります。ブラシ径最大2048px、文書辺長最大65536px、読み込み画像は64M画素以下。深い効果スタックや大きなROIではGPU予算に達する場合があります。
4. 旧render v1・v2文書はサポート対象外です。render v3の整数経路は、記録済みのCPU参照・GPU parity ケースで全バイト一致を確認していますが、すべてのGPU・操作の組み合わせを網羅した保証ではありません。Undoの正本は読み戻した結果で保持します。
5. 等倍で軸に沿う表示は最近傍、それ以外のライブ変形はバイリニアです。`image` APIの90度回転・反転は整数画素操作、拡縮はnearest/bilinearです。`canvas` APIはルート変形で文書全体を動かし、画素を書き換えません。Catmull-Romと面積縮小は後続です。コンテンツミップマップは未実装です。
6. CPU正本はLZ4。保存したあと、およびパッケージを開いたあとは、現在の文書と Undo / Redo が参照しない版のタイルを常駐から外し、読むときにハッシュを検証して戻します。未保存のあいだは版のタイルも常駐です。復号キャッシュは128MiBのLRUで、常駐タイルだけを保持します。OPFSは作業ジャーナルのままです。開いたフォルダからタイルを遅延読み込みする階層は未実装で、退避先はメモリ上のパッケージオブジェクトです。
7. オリジン当たり1作業領域です。Web Locksで二重起動を拒否します。複数文書を並行編集するための文書別ジャーナル分離は未実装です。
8. M7/M8最終版はこのMacの内蔵Chromium 152（Claude 2.42304）で確認しました。M6はChrome 155と内蔵Chromium 155で確認済みです。Chrome/Edge/Firefox/SafariでのM7/M8、異なるGPU、長時間運用とファジングは未検証です。現行文書・版管理にはEngine/WASM 0.4.0、TypeScript SDK 0.5.0（追加実装はプロトコル7）が必要です。
9. パス当たり4096命令、レイヤー当たり128パス/16384命令、座標は±1048576以内。線幅0〜4096px、miter limit 1〜64。メッシュ生成には頂点/インデックス上限があり、GPUメッシュキャッシュは32MiBとGPU全体の残予算で制限します。
10. ラスター確定グラデーションとSVGの限定インポートに対応しました。ベクター塗りのグラデーション、破線、SVGのCSS・画像・文字・外部参照は未対応です。パスデータの円弧はCubicへ正規化します。GPUメッシュは局所原点からf32で保持するため、極端に大きい形や変形では数値精度に限界があります。M6の解析曲線テストは表示レベル16段階で輪郭誤差1.2出力px以内を確認しています。
11. テキストは1レイヤー16384 UTF-16単位、span・縦中横範囲は各1024、フォールバック16書体、OpenType機能64個まで。縦中横は1範囲8 UTF-16単位まで。ルビ・圏点・割注・ぶら下げ・字下げ・段落ごとの揃え・下線・斜体の合成・可変フォントの軸指定・カラーフォント（絵文字）は未実装です。
12. 画面上のemが24px未満の文字はサイズ帯ごとのグリフアトラス（面積被覆・1/4pxの位相）、以上はベクター経路（4x MSAA）で描きます。ヒンティング・ステム強調・ガンマ補正・サブピクセル（LCD）描画は行わないため、極小サイズはOSの文字描画より柔らかく見えます。アトラスとベクターの差は4x MSAAの1/4刻みの被覆による画素単位の揺れ程度です（12px前後でインク量の差1%以内、行・列の投影の相関0.98以上）。アトラスは1024²の1枚で、同じフレームの文字がそれを使い切った場合、残りはベクター経路で描きます。縦組みの向き分類はUAX #50の主要ブロックを網羅した簡略表です。
13. 双方向テキストは段落の基底方向を自動判定し、行ごとに並べ替えます。アラビア文字等の字形は与えたフォントの機能に依存し、縦組み中のRTL文字は横向きに回転するだけです。
14. 版管理はDAGで、ブランチ・保護・タグ・pin・二親マージと競合解決に対応しました。GCの既定はdry-runです。ネイティブのフォルダ/ZIP、SDKのメモリ保存先、OPFSフォルダは実削除に対応します。OPFSはオリジン内のWeb Locksで全SDK writerを排他します。File System Accessで選んだフォルダは他のオリジンやネイティブのアプリを排他できないため確認のみです。到達する古い履歴の打ち切りや分散同期は含めません。[設計](design/VERSIONING-AND-IMAGE-EDITING.md)を参照してください。
15. `alto-git` はブランチ・タグ・二親マージをGitのrefと同じ順序のparentsへ写します（[第8.1節](design/VERSIONING-AND-IMAGE-EDITING.md)）。ネイティブCLIで、`git` コマンドが必要です。予期しないGit refの変更は `CONFLICT` です。ブラウザ内でのgit操作、Git側の変更の取り込み、rebase、cherry-pickは未実装です。
16. M7/M8初期計測の本体WASMは4,093,058 bytes / gzip 1,034,059 bytes（M6比 +1.5MB / gzip +434KB）。主にrustybuzz・ttf-parserとUnicodeの表です。WASMキャッシュ済みの起動（B7）は1.29秒で目標内です。
17. 内蔵Chromium 152ではWorkerからWorkerを起動できないため、Storage Workerが起動・応答しない場合はEngine Worker内で同じOPFSジャーナル処理を実行するフォールバックを入れました（その場合ジャーナル書き込みはEngine Worker上で同期実行されます）。
