# Safari 性能改善の計測記録（2026-11-23）

## 条件

- Safari 27.2 / macOS（Apple M5, GPU 10 コア, MacBook Air・ファンレス）/ 内蔵 Retina 2560×1664
- ウィンドウ 1400×790、DPR 2、キャンバス 2180×1294 px、`benchmarkView=physical`（元報告と同一）
- 文書・手順: Playground の「B1〜B7を計測」（`tests/e2e/browser-tests.js` の `benches`）をそのまま実行。プロファイリング無効。
- 計測ページは毎回新しいポート（新しいオリジン）、`Cache-Control: no-store`。他に Claude / Codex / opencode が常駐（低負荷）。
- 変更前のビルド成果物は元報告（`alto-verification.json`）時点と同一（`alto_wasm_bg.wasm` SHA-256 `04ae8324…`）。

### 計測上の注意

- **Safari の状態で値が大きく変わる。** 長時間起動した Safari では、変更と無関係な B4 や B1 を含め全体が約 2 倍遅い。タブを閉じても WebContent プロセスが約 1 GB 残っていた。下の「クリーン」は各回の前に Safari を終了・再起動した値。
- 連続計測を 10 分ほど続けると、変更の有無に関係なく 2〜3 倍遅くなるラウンドがあった（ファンレス機の発熱か Safari の蓄積かは未切り分け）。そのラウンドは比較から除外し、変更前後を交互に、各回 60〜75 秒の間隔を空けて計測した。

## 原因（計測で確認したもの）

- **B5 / B7:** 診断用ビルド（区間タイマー入り, 製品には含まない）で、開く処理 3.1 s のうち BLAKE3 ハッシュ 2.03 s、LZ4 展開 0.47 s。B7 の初回描画は、復旧後のタイルをデコードプールで照合するハッシュが大半。BLAKE3 がスカラー実装だった。
- **B8 zoom 1:** 小さなストローク 1 回で表示タイル 9 枚（3×3）を作り直し、各タイルの合成で Worker に 2 回制御を返していた。合成を投げた後の待機が毎回約 6 ms（CPU は合計 5 ms 程度）。MessageChannel の待機自体は 1 ms 未満で原因ではない。3×3 になるのは、v3 の正確な到達範囲（2×2）に加え、v1/v2 向けの 2 px 余白つき矩形でも無効化していたため。
- **B8 全体表示:** 親タイル生成を 8 ステップごとに区切り、各回 GPU キュー完了を 5〜8 ms 待っていた（約 4 回）。③で作り直す親タイルが減り、待ちが発生しなくなった。上限の緩和は不要と判断し、見送った。

## 変更

1. `alto-core`: `blake3` の `wasm32_simd` を有効化（同じダイジェスト、wasm32 のみ）。
2. `alto-gpu` frame.rs: 表示タイルのジョブを、CPU 処理の間はフレーム予算（8 ms）内で続ける。デコードプール待ちのときは従来どおり Worker に返す。診断では 1 ティックの CPU は 1〜2 ms。
3. `alto-gpu` stroke.rs: v3 の `Damage::Sources` は `exact_reach` だけで無効化する（ソースのない矩形は従来どおり）。

## 正確性の検証

- ネイティブ GPU（Metal）の cold/warm 比較に、編集タイル周囲のレベル 0 の 16 枚とレベル 1 の 4 枚を、恒等・小数平行移動・負の平行移動・拡大回転で確認するケースを追加。warm = cold = CPU。ソース側の無効化を外すと失敗する（変異テストで確認）。
- `cargo test --workspace` 全件合格。fmt と clippy（`-D warnings`、wasm32 を含む）も通過。
- SDK: `node --test` 83 件、`api:check` 合格。
- Chrome（ヘッドレス, `scripts/verify-browser.mjs`）: functional 57、parity 191、image-versions 30、m5 14、m6 11、m7 13、m8 6、すべて合格。
- Safari（ハーネス経由で同じスイートを実行。WebDriver はリモートオートメーション無効のため不使用）: functional 56、image-versions 30、m5 14、m6 11、m7 13、m8 6 合格。「編集後に残したタイルと全再合成の一致」、GPU 消失からの復旧、Undo/Redo を含む。
  - 以下は変更前ビルドでも同じく失敗・停止する既存の問題:
    - functional「low-zoom prefetch」が DPR 2 で失敗（`codex/fix-prefetch-test-dpr` で修正済みのテスト不備。検証ではその修正を当てて実行）
    - functional「decode worker that stops answering」が停止（検証では飛ばした。Chrome では合格）
    - parity「cold v3 pyramid … bounded submissions」（1 ティック 9 ステップ）
    - embed「recent files」
