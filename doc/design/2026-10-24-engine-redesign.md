# エンジン再設計：差分描画・エラー一本化・編集コストの線形化

作成日：2026-10-24
対象ブランチ：`redesign/incremental-render-and-errors`（`codex/performance-recovery-v2-20261022` から分岐）

## 1. なぜ再設計するのか

`codex/performance-recovery-v2` の 25 コミットは、キャッシュが空の状態からの描画（コールド描画）を中断可能にし、先読みすることに費やされた。しかし、コールド描画が頻繁に起きる最大の原因はエンジン自身にある。

- `alto-wasm` の `Runtime::refresh()` は、すべての編集（transact・undo・redo・ブラシ確定・選択・マスク・効果など 9 か所）の後に `renderer.invalidate(None)` を呼び、表示タイルのキャッシュを全部捨てている。
- 文書側は変更範囲（`ChangeSet.dirty`）を計算しているが、描画側に届いていない。
- ストロークの確定時とキャンセル時も全部捨てる。変形済みレイヤーへのブラシ入力では、入力のたびに全部捨てている。

その結果、4K・20 レイヤーの文書で 1 ピクセル塗るだけでも、画面全体の合成をやり直す。中断可能なジョブと先読みは、この症状への対症療法である。

同時に、次の問題も見つかった。

| # | 問題 | 場所 |

| P13 | undo / redo がジャーナルに通常の編集として記録され、復旧後の取り消し履歴がクラッシュ前と変わる | `alto-wasm/src/lib.rs` `undo()` / `redo()` |

## 2. 目標と、目標にしないこと

### 目標

- 編集後に作り直す表示タイルを、変更した範囲に限る（P1）。
- タイルの読み出しエラーを、副経路ではなく戻り値で伝える（P3、P4）。
- 1 回の編集のコストを、文書と履歴の大きさに対して線形以下にする（P2、P5）。
- 4K 級のレイヤー全体を、自動選択で選べるようにする（P6）。
- メモリリークとエラーの誤分類をなくす（P7、P8）。
- 描画器の状態を、引数で渡せるものは引数で渡す（P9）。

### 目標にしないこと（今回は範囲外。第 2 段階で扱う）

- クレート構成の変更（P10）。描画シーンの型を `alto-scene` に切り出す。
- タイル保存のスレッド対応（P11）。
- Worker の I/O と描画の分離、増分チェックポイント（P12）。
- ジャーナルの undo / redo の意味の修正（P13）。チェックポイントが取り消し履歴を持たないため、単独では直せない。
- JSON を介した WASM 境界の置き換え。

### 失敗とみなすこと

- 差分描画によって、ピクセルが 1 つでも以前と異なる。差分の計算に自信が持てない場面では、必ず全体を無効化する。
- `.alto` 形式、ジャーナル形式、SDK の公開 API を変える。

## 3. 制約

- Rust 1.99.1、wasm-bindgen 0.2.129 で固定。WASM はリポジトリに置き、ビルドし直したバイト列と一致させる（`scripts/check.sh`）。
- `cargo fmt`、`cargo test`、`cargo clippy -D warnings`（ホスト用と wasm32 用）が通ること。
- ブラウザでの機能テスト（`node scripts/verify-browser.mjs --functional`）が通ること。

## 4. 設計

### 4.1 差分描画（P1）

**方針：** 描画シーンの新旧を比べて、表示が変わりうる範囲（ダメージ）を文書座標の矩形で求め、その範囲に重なる表示タイルだけを無効化する。

文書側の `ChangeSet.dirty` を使わずにシーン同士を比べる理由は次のとおり。

- `dirty` を埋めているのは `SetTiles` だけで、変形・不透明度・表示切替・並べ替えでは空になる。
- シーンは描画器が実際に見る入力そのものである。シーンを比べれば、文書操作の種類に関係なく、描画に効く違いだけを確実に拾える。

**新しい関数：** `alto_gpu::damage::scene_damage(old, new) -> Damage`

```rust
pub enum Damage {
    None,
    Rects(Vec<Rect>),   // 文書座標
    All,
}
```

**判定の規則：**

1. キャンバスの範囲が違う場合、またはどちらかのシーンが「単純なシーン」でない場合は `All` を返す。単純なシーンとは、マスク・ベクターマスク・クリップパス・下のレイヤーでのクリップ・効果・調整レイヤー・メッシュ・テキストを含まないシーンを指す。この判定は描画器の「中断可能なシーン」の判定と同じ関数を使う（`plain_scene()`）。単純なシーンでは、合成がすべてピクセル単位の演算なので、範囲を限った無効化が厳密に正しい。
2. 各ノードについて、ルートからの累積変換と実効的な表示状態（自分と祖先がすべて表示中で、不透明度が 0 より大きい）を計算する。
3. ノード ID で新旧を突き合わせる。
   - 片方にしかないノード：そのシーンでの部分木の範囲をダメージに加える。
   - 両方にあり、どちらでも非表示：何もしない。
   - グループ：表示状態・累積変換・不透明度・合成モード・分離の有無・子の ID の並びのどれかが違えば、新旧両方の部分木の範囲を加える。
   - タイルのレイヤー：表示状態・累積変換・不透明度・合成モードのどれかが違えば、新旧両方のレイヤー全体の範囲を加える。同じなら、タイルの一覧を突き合わせ、ハッシュが違うタイル（追加・削除を含む）の範囲だけを加える。
4. タイルの範囲は、256×256 の矩形を累積変換で文書座標に写した外接矩形に、サンプリング用の余白を加えたもの。余白は変換の最大拡大率に 1 を足したピクセル数とする。
5. 矩形が 64 個を超えたら 1 つの外接矩形にまとめる。

**呼び出し側の変更（`alto-wasm`）：**

- `refresh()` は、新しいシーンを作ってから `scene_damage(&old, &new)` を計算し、`Damage` に応じて描画器を無効化する。
- `Renderer::invalidate_damage(&Damage)` を追加する。`Rects` の場合は、矩形ごとに既存の `invalidate(Some(rect))` の判定でキャッシュを消す。
- 進行中の表示ジョブと先読みジョブは、シーンが変わったら必ず破棄する。ジョブはシーン内のノード番号を保持しているため。

**ストローク：**

- `stamp()` に、レイヤー座標から文書座標への変換を渡す。描画器は、文書座標でのストロークの範囲を `GpuStroke` に累積する。
- `stamp()` の無効化は、文書座標の範囲で行う。変形済みレイヤーで毎回全体を捨てていた処理は不要になる。
- `finish_stroke()` と `cancel_stroke()` は、累積した範囲だけを無効化する。
- `end_brush()` で transact が失敗した場合は、全体を無効化してから失敗を返す。表示に、確定していないストロークが残らないようにするため。

### 4.2 タイル読み出しのエラー（P3、P4）

- `TileStore::get()` の戻り値を `Result<Option<Arc<TileData>>, TileError>` に変える。`Ok(None)` は「無い」、`Err(TileError::Corrupt(hash))` は「壊れている」を表す。
- `get_checked()`、`fault` フィールド、`take_fault()`、`Engine::take_fault_error()` を削除する。
- `TileError` に `Corrupt(ContentHash)` を追加し、`Display` は `CORRUPT_DATA: corrupt object <hash>` とする。
- `Engine::tile()` は `Result<Option<Arc<TileData>>, EngineError>` を返す。必ず存在するべき場面のために `Engine::require_tile()`（旧 `tile_checked()`）を置く。
- `Engine::encoded()` は `Result<Option<Vec<u8>>, EngineError>` を返す。
- `journal_record()` は、参照しているオブジェクトが取り出せない場合にエラーを返す。黙って飛ばさない。
- テスト専用の `tamper_parked_tile()` / `tamper_cold()` は `#[cfg(test)]` 付きの公開関数か、`test-hooks` feature の裏に置く。`alto-engine` のテストが使うため、`alto-raster` に `test-hooks` feature を設ける。

### 4.3 `maintain()` の線形化（P2）

- `Editor` に、取り消し・やり直し履歴の操作を参照で巡回する関数（`for_each_retained_op(&self, f)`）を追加し、複製をやめる。
- 履歴が参照するハッシュの集計を、取り消しを落とすたびに最初からやり直すのではなく、1 回の集計で「古い順に何件落とせば上限に収まるか」を決めてから落とす。取り消し 1 件ごとのハッシュ集合を古い順に足していき、現在の文書にないハッシュの数が上限を超えた時点で、その手前までを残す。
- 上限（履歴だけが参照するタイル 2048 個）は今回は変えない。

### 4.4 CPU のピクセル処理（P5）

- `Scratch` をタイル単位の書き込みに変える。`paint_layer` と同種の処理は、タイルごとにピクセル配列を 1 回確保し、配列の添字で直接書く。座標から BTreeMap を引くのは、タイルをまたぐ参照が必要な処理（移動など）に限る。
- 文書全体の複製（`self.document(handle)?.clone()`）をやめ、必要なノードと revision だけを取り出す。

### 4.5 自動選択（P6）

- 訪問済みの記録を、タイルごとの 65,536 ビットのビット集合（`BTreeMap<TileKey, Box<[u64; 1024]>>`）に変える。4K 全体でも約 1MB に収まる。
- 選択済みピクセルも `Vec<(i32,i32)>` で集めず、出力のマスクタイルに直接書く。
- 走査は行単位で塗り広げる方式（スキャンライン）に変え、キューの長さを抑える。
- 固定の 1,048,576 ピクセルの上限をやめる。選択の上限は既存の「選択マスク 4096 タイル」で一本化し、塗り広げの途中でも超えた時点で止める。
- 対象レイヤーの上限を 32 タイルから 1024 タイル（約 6,700 万ピクセル）に上げる。訪問済みのビット集合は 1 タイル 8KB なので、1024 タイルでも 8MB に収まる。
- レイヤーのタイルは 1 枚だけ手元に保持し、ほかはタイル保存の展開キャッシュに任せる。全タイルを展開して保持すると、1024 タイルで 256MB になるため。

### 4.6 Worker（P7、P8）

- SDK の `save()` / `saveFolder()` が失敗またはキャンセルされた場合は、新しい `releaseSave` 要求で Worker の token と、パッケージのコピーを解放する。
- 確定も解放もされない経路（テスト用の `saveBytes` など）に備えて、Worker が保持する保存待ちは最大 4 件とし、超えたら古いものから捨てる。最新の 1 件だけにしないのは、保存を 2 回続けて押したときに 1 回目の確定が失敗しないようにするため。
- `DocError` と `EngineError` の表示文の先頭に、SDK のエラーコード（`INVALID_ARGUMENT:`、`NOT_FOUND:`、`CONFLICT:`）を付ける。内側で二重に付けていた接頭辞は外す。
- `structured()` は、既知のコードに当てはまらないエラーを `INTERNAL` に分類する。ただし serde が不正な要求を拒否した文（`at line N column M` を含む）は `INVALID_ARGUMENT` とする。利用者が渡した値の型の誤りであるため。

### 4.7 描画器の整理（P9）

- 呼び出しのたびに書き換えていた `profile_now` フィールドを削除する。時計は描画器の生成直後に `set_clock()` で一度だけ設定する、固定の依存とする。`render()` / `prefetch_step()` の `now` 引数は削除する。
  - 引数で渡す案は採らなかった。`upload()` は選択・マスク用の描画経路（`renderer/m5.rs`）からも呼ばれ、そこまで時計を通す必要があるため。
- `prefetching` フラグを削除する。`upload_timed()` が取得・変換・書き込みの所要時間を `UploadCost` として返し、先読みの統計は呼び出し側（`advance_tile_job`）が集計する。
- 四隅を逆変換して外接矩形を求める処理を `fn bounds_through(m, rect) -> ([f64;2],[f64;2])` にまとめる。
- `const JOB_SLICE_MS: f64 = 1.8;`、`const MAX_JOB_RETRIES: u32 = 8;`、`const SCRATCH_BYTES: u64 = 512 * 512 * 4;` を定義する。
- `PrefetchStep` を `JobStep` に改名する。WASM が返す文字列（`"idle"` など）は変えない。
- `resumable_scene()` と `compose()` 冒頭の重複した判定を、4.1 の `plain_scene()` にまとめる。

## 5. 検証

- **差分描画：** `scene_damage` に単体テストを書く。対象は、タイル 1 枚の変更、変形の変更、表示切替、並べ替え、グループの不透明度、ノードの追加と削除、単純でないシーンでの `All`。
- **ピクセルの一致：** 既存のブラウザの機能テストが、表示タイルを読み戻して参照画像と比べている。これを全件通す。差分描画の前後で、同じ編集手順から同じピクセルが得られることを確かめる。
- **エラー：** 破損したタイルが `Err(Corrupt)` になること、その後の無関係な読み出しが成功すること、ジャーナル記録が欠けたオブジェクトでエラーになることをテストする。
- **maintain：** 長い履歴で、取り消しを落とした結果が以前と同じになることをテストする。
- **自動選択：** 2048×2048（旧上限の 4 倍）の単色レイヤーで全体が選択されること、壁・すき間・囲まれた領域・タイルの無い場所を正しく扱うことをテストする。
- 最後に `scripts/check.sh` と `node scripts/verify-browser.mjs --functional` を実行する。

## 6. 実装する人に任せること

- `scene_damage` の矩形をまとめる上限（64）と、余白の計算は目安。テストで正しさが確かめられれば調整してよい。
- `maintain()` の新しい集計で、取り消し 1 件ごとのハッシュ集合をどう持つか。

## 7. 第 2 段階（別の変更として行う）

1. **`alto-scene` クレートを作る（P10）。** `RenderScene`・`RNode` などの型と行列計算を移し、`alto-engine` から `alto-gpu` への依存をなくす。行列計算は `alto_core::Affine2` に一本化する。
2. **タイル保存を、圧縮データの保存部分と展開キャッシュに分ける（P11）。** 保存部分は読み出しで内部の状態を書き換えないので、スレッドをまたいで共有できる。展開キャッシュは描画側が持つ。
3. **Worker の I/O と描画を分ける（P12）。** ジャーナルの書き込み完了を待たずに描画を続ける（新しい編集だけを待たせる）。チェックポイントは、変更のあったオブジェクトだけを書く増分方式にする。
4. **チェックポイントに取り消し履歴を含め、ジャーナルの undo / redo を本当の undo / redo として再生する（P13）。**
5. **WASM 境界のデータ受け渡しを JSON から型付きのバイナリ形式に変える。**
