# Render version 3 as the new-document default

This memo supersedes the opt-in and unfinished-stage statements in the earlier
v3 design notes. They remain useful records of how the integer pipeline was
built. Version 1 and 2 files still use their original renderers and keep their
stored format and pixel behavior until an explicit upgrade.

## Document lifecycle

- `DocumentMeta::srgb_u8` and SDK `createDocument` create render version 3,
  format 4. `createDocument({ ..., renderVersion: 2 })` and
  `DocumentMeta::srgb_u8_v2` are explicit compatibility constructors.
- Saving a version-3 package, folder, or trimmed history needs no opt-in. A
  version-3 package can be reopened and saved without changing its bytes.
- `upgradeRenderVersion` moves a version-1 or version-2 document to version 3
  as one undoable edit. It writes format 4 and regenerates every text bake in
  the same transaction. Loading and saving do not upgrade old documents.
- The old `unstableRenderV3` option, classifier and Rust opt-in symbols remain
  callable for source compatibility but do not gate the stable path.

## Integer rendering stages

The existing Q14 compositor and blur path now also cover strokes and clipped
layer chains. All document effect kinds have Q14 stages, whether used on a
layer or an adjustment layer. Selection masks mix the unfiltered and filtered
Q14 values. Adjustment vector masks and clip paths use a third Q14 texture for
coverage. Non-normal adjustment blending uses the same integer mode 23 with or
without a pixel mask.

The new effect modes are 30 invert, 31 curves, 32 levels and 33 hue/saturation.
Invert and curves operate on straight Q14 channels and premultiply once at the
end. Curves store up to 16 quantized control points in integer uniform words.
Levels normalizes by its quantized input span and evaluates `x^(1/gamma)` via
integer log2 and exp2 iterations; the exp2 roots are fixed Q14 constants. Gamma
is quantized over its full document range, 0.1 to 10.
Hue/saturation quantizes degrees to Q16, obtains sine and cosine from a 16-step
integer CORDIC rotation, then uses integer luma and a wide signed mix. These
formulas define version-3 output; versions 1 and 2 retain their float formulas.

At zoom levels -6 through -1, raster and mask sampling encode the ROI origin
in the level's grid units and its scale as a negative power-of-two denominator.
The shader converts these pixel centers to Q8 exactly. Input textures use a
common integer grid to map pixels between levels; reach checks use the same
Q8 centers before deciding which source tiles to upload.

The direct layout-run `RContent::Text` form is still an invalid version-3 scene
input. Document text is baked before rendering and arrives as `TextBake`.

## Verification

Metal tests exercise every new effect as both a layer effect and an adjustment
layer, as well as stroke caps, joins, transformations, clipping and vector
coverage. The browser parity suite compares the shipped WebAssembly renderer
with its integer reference, while explicit version-2 documents preserve the
legacy pixel fixtures. The new-document browser test checks version 3 and
format 4 through save and reopen.

## Locked hashes

Version 3 output is locked, not only compared with a reference. In
`tests/parity/cpu-reference.txt`, the `v3-` lines are the Rust CPU reference of
the measured composite catalog at level 0 and its level 1 pyramid. Metal must
match them, and so must the browser's JS reference and GPU tile. The ten
`text-v3-` lines lock text. `tests/parity/v3-browser.txt` locks every other
enforced v3 browser tile, such as blur, vector, masks and the color effects, by
FNV-1a. A tile missing from either file, a stale or duplicate entry, or a Rust
`v3-` line that no enforced tile checked fails the parity suite. Regenerate the
browser file with `ALTO_WRITE_V3_BROWSER=1 node scripts/verify-browser.mjs
--suite=parity`, which writes only after a passing run. Regenerate the Rust
lines with `ALTO_WRITE_PARITY=1 cargo test -p alto-gpu cpu_reference`.
