# 画像編集のための設計

2026-10-20。v0.4 の正本（Scene Graph、可逆 Op、内容アドレスのタイル、GPU は派生）を維持したまま、画像編集ソフトが必要とする操作を載せるための設計です。到達と常駐の分離、head から N 代のパッケージ、GPU 予算のフレーム優先、17 種の合成、等倍以外のバイリニア、レベル・カーブ・色相彩度・反転、切り抜き・90 度回転・反転・画像サイズ、`ReplaceNode`、ラスタライズ、結合、1:1 書き出し、スポイト、色域と連続選択、塗り、グラデーション、スタンプ、指先はエンジンの Rust API に入っています。ミップマップ、残りの効果、WASM と SDK への公開（プロトコル 5）は未実装です。現行の上限は [MILESTONES.md](../MILESTONES.md) です。

## 維持すること

- 編集は Transaction の中だけで起き、各 Op は逆 Op を持つ。版の復元は履歴を書き換えず、1 回の Undo で戻せる Transaction である。
- 画素の正本は 256px の RGBA8 または R8 タイルで、BLAKE3 が識別子である。GPU のテクスチャ、メッシュ、グリフアトラス、ミップは捨てて正本から作り直せる。
- 保存は sRGB / RGBA8 と R8 のままである。効果の途中計算は今と同じ RGBA16F を使い、確定した画素だけを RGBA8 へ戻す。`ColorSpace::DisplayP3` と `BitDepth::U16` / `F16` は保存形式に使わない。
- 選択とマスクは R8 タイル 1 枚のマップである。新しい選択ツールは生成器を足し、選択の型は足さない。
- 合成モードの列挙は `BlendMode` のままである。ノード種別は Group、Raster、Vector、Text、Adjustment、Unsupported のままである。グラデーション塗りは新しい種別を作らず、ラスターへの `SetTiles` として確定する。
- `.alto` と `.altoproj` は同じエントリを共有する。オブジェクトは不変で、manifest は最後に書き、楽観ロックを維持する。版は first parent の 1 本のままである。
- Main は入力と読み取り専用ミラー、Engine Worker が文書と GPU、Storage Worker が OPFS ジャーナルである。

## 到達と常駐を分ける

`Engine::maintain` は今、現在の文書、Undo / Redo、各版の `retained`、読み込み中のハッシュを一つの `keep` にし、`MemoryTileStore::retain` でそれ以外の圧縮バイトを捨てている。版が参照するタイルは、パッケージの GC 根であると同時に RAM の常駐集合にもなっている。コピースタンプのように近傍を読むツールと、長いペイントは、この同一視のままではヒープが先に尽きる。

二つの集合に分ける。

| 集合 | 含むもの | 捨ててよいか |
|---|---|---|
| 到達 | 現在のノード、選択、Undo / Redo が参照するハッシュ、版の `retained`、`pin_import` | パッケージからも消してはならない |
| 常駐 | 現在のノード、選択、Undo / Redo、実行中ストロークがピンしたハッシュ、直前に復元した 1 版 | RAM から落としてよい。到達に残っていればパッケージから読み戻す |

規則は次のとおりです。

- Transaction の事前条件は「ハッシュが到達に含まれる」ことである。常駐していること、は条件にしない。
- `TileStore::get` は常駐に無ければ、開いているパッケージの `ObjectStore` から同じハッシュを読む。読んだバイトは内容ハッシュを再検証してから常駐へ入れる。検証に失敗したオブジェクトは、今のパッケージ読み込みと同じく破損として扱う。
- まだ一度も保存していない文書には裏のパッケージが無い。その間は到達と常駐を同一にし、保存が成功した直後の `maintain` から版のタイルを常駐から外してよい。
- Undo が現在の文書に無いタイルを 2048 までしか持たない既存の弁は、常駐側の弁として残す。版の到達集合にはこの弁を適用しない。版を黙って削除しない。
- 古い版をファイルから外す操作は、開いている履歴を書き換えない。保存時に「head と、そこから N 代のコミットだけを根にしたパッケージ」を別のファイルへ書く。`export` / `pack` と同じ種類の写しである。

復号 LRU の 128MiB は常駐の中の展開キャッシュとして維持する。OPFS はジャーナルのままです。正本タイルの退避先は、開いている `.alto` または `.altoproj` の `objects/` です。

Storage Worker に落ちた環境では、チェックポイントのバイト列をフレームをまたいで小分けに書く。ジャーナルの 1 レコードは今どおり原子的で、一時名へ書き切ってから確定する。レコード形式と二重チェックポイントは変えない。

## GPU 予算を二口座にする

計測上の上限は、表示キャッシュとメッシュとアトラスが予算を埋めたあとで、フレーム本体が残量に乗ることです。合成モード、ミップ、近傍フィルタはフレーム本体を増やします。

`ResourceManager` の総予算はそのまま、確保順だけを変えます。

1. フレーム口座を先に取る。ビューポートの表示タイル、実行中のストローク対象、そのフレームの効果用 RGBA16F と ROI です。
2. 残りをキャッシュ口座にする。メッシュキャッシュ（上限 32MiB）、グリフアトラス、表示タイルの余剰はここからのみ確保する。
3. フレーム口座が総予算を超えるときだけ、今と同じ `INVALID_ARGUMENT` を返す。超える前に、ピンされていないキャッシュを落としてフレームを再試行する。
4. フレーム末の追い出しは今どおり、ピンされていない派生から行う。追い出し順は変えない。

ミップと合成の作業テクスチャはフレーム口座です。文書へは書きません。

## サンプリング

正本のタイルはフィルタ前の画素です。補間結果をタイルとして保存するのは、利用者が解像度変更や変形の適用を確定したときだけです。

三つの経路を分けます。

| 経路 | いつ | カーネル | 保存 |
|---|---|---|---|
| 正対の 1 画素 | 文書座標が整数で、軸平行・等倍 | 点サンプル（今の `textureLoad`） | しない |
| ライブ変形 | レイヤーの `Affine2` が等倍軸平行でない、またはビューが拡大している | バイリニア | しない。派生 |
| 確定リサンプル | 画像サイズ、回転、反転、非タイル境界の切り抜き、変形の適用 | Catmull-Rom | 新しいハッシュのタイル |

縮小表示の段は、正本ハッシュとレベルの派生ミップにする。今の 2×2 平均はレベル 1 の生成に使い、それより粗いレベルは直前のレベルから同じ平均で作る。ミップはキャッシュ口座に置き、デバイス喪失後は正本から作り直す。パッケージには入れない。

画面への最終出力（`present.wgsl` の線形サンプラ）は維持する。ライブ変形のバイリニアと、この最終出力の線形は別の段です。

## 合成モード

`BlendMode` は Overlay、Soft Light、Color、Luminosity まで既に持っています。`alto-engine` は Normal、Multiply、Screen 以外を `RenderBlend::Other` にし、シェーダはそれを Normal（モード 0）として描きます。保存されたモードと表示が一致しません。

`RenderBlend` を `BlendMode` と一対一にします。`Other` は廃止します。シェーダのモード番号は列挙の定義順で、文書に無い番号は計画エラーにします。未実装のモードを Normal で代用しません。

計算は効果経路と同じ RGBA16F、プレマルチプライドで行います。列挙にあるモードは同じ変更で全部接続します。一部だけ残して再び `Other` に落とさないためです。確定画素は RGBA8 のままです。

この変更はファイル形式を変えません。モード名は既にスナップショットへ書けます。表示だけが、保存されている名前へ揃います。

## 効果

ディスク上の表現は、今のタグ付き JSON（`type`）のままです。`gaussian_blur` と `color_adjust` のフィールドと範囲は変えない。Rust 側の検証を `serde_json::Value` のまま広げず、`Effect` 列挙へします。`LayerProps.effects` と調整ノードの中身は、その列挙のシリアライズ結果です。未知の `type` は今どおり原子的に拒否します。

先に足す型は次です。空間フィルタの半径単位は、今のガウスと同じくレイヤー変形後の文書 px です。ノード当たり 32 個、半径 0〜64 は維持します。

| type | フィールド | 範囲 |
|---|---|---|
| `levels` | `in_black` `in_white` `gamma` `out_black` `out_white` | 入出力は 0〜1、`in_black` < `in_white`、ガンマは 0.1〜10 |
| `curves` | `channel`（`master` / `red` / `green` / `blue`）と `points`（`x` `y`） | 点は 2〜16、両端を含む、`x` は狭義単調増加、座標は 0〜1 |
| `hue_saturation` | `hue` `saturation` `lightness` | 色相 −180〜180、彩度 0〜4、明度 −1〜1 |
| `invert` | なし | |

`selection` フィールド（効果へ焼き付いた R8）は全タイプで今どおり任意です。評価順は配列順、入力は今の調整レイヤーと同じ「同じグループの下側」またはノード自身の画素です。ヒストグラムは効果ではなく読み取り API です。対象レイヤーの正本タイル、または文書矩形を、チャネルあたり 256 ビンで返します。文書へは書きません。

後から同じ列挙へ足すタイプは、アンシャープマスク、移動ぼかし、ノイズ、ハイパス、ドロップシャドウ、境界線です。それぞれが既存の ROI と効果スタックを使います。パラメータが決まるまで `validate_effect` は未知タイプとして拒否したままにします。

## キャンバスの幾何

`SetMeta` は寸法の数値を入れ替えるだけで、タイルキーやパス座標は動きません。切り抜きや解像度変更を `SetMeta` 単独で表すと、画素とキャンバスがずれます。

幾何の変更は 1 つの Transaction にまとめ、既存の Op の逆で 1 回の Undo にします。API はエンジン側に置き、呼び出し側が Op を組み立てません。

- **切り抜き。** 引数は文書座標の矩形です。矩形の最小隅が新しい原点 (0, 0) になるよう、文書全体を平行移動します。対象はラスターのタイルキー、マスク、選択、効果に焼き付いた R8、ベクターの座標、テキスト枠、各ノードの `Affine2` の平行移動成分です。タイル境界に揃う移動はハッシュを変えずキーだけを張り替えます。境界がタイルの途中なら、分断されるタイルだけを Catmull-Rom ではなく画素の切り出しで新しいハッシュにします（補間しない）。最後に `SetMeta` で幅と高さを矩形の大きさにします。
- **回転と反転。** 90 度単位と、水平・垂直の反転だけです。画素をタイル内で並べ替えて新しいハッシュを作り、キーを新しい寸法へ対応させ、文書空間の座標と平行移動を同じ変換で更新し、`SetMeta` で幅と高さを入れ替えます。任意角はレイヤーの `Affine2`（ライブ変形）のままです。
- **画像サイズ。** 幅と高さの倍率で、文書空間の量をすべてスケールします。ラスターと R8 は Catmull-Rom で新しいハッシュへリサンプルします。ベクター座標、テキストの枠と文字サイズ、ノード変換の平行移動も同じ倍率です。倍率の成分が幅と高さで違っていても受け付けます。

いずれの操作も、参照する新しいハッシュを先にストアへ置き、その後で Transaction を適用します。途中の Op が拒否された場合は、今の Transaction と同じく文書を変えません。

## ベイクと書き出し

ベクターとテキストは `SetTiles` の対象になれません。ラスタライズはノードの種別を変えます。種別の変更は `Op::ReplaceNode { id, node }` で表します。

- `node.id` は `id` と一致し、親と兄弟順は変わりません。NodeId を維持するので、版の意味的差分は削除と追加になりません。
- 逆 Op は置き換え前のノードです。置き換え前のタイルハッシュは Undo の到達に残ります。
- スナップショットの JSON に新しいフィールドは出ません。ノードそのものが置き換わるだけです。`ReplaceNode` が現れるのはセッションのジャーナルと Undo です。

**ラスタライズ**は、対象ノードをローカル画素へ 1:1 で描き、効果・マスク・ベクターマスク・クリッピングパス・レイヤー変換をその画素へ焼きます。種別を Raster にし、変換は恒等、効果とマスクは空にします。名前、親、不透明度、合成モード、表示、ロックは残します。グループのラスタライズは、子を合成した 1 枚のラスターでグループノードを `ReplaceNode` し、子を `RemoveNode` します。これも 1 Transaction です。

**表示レイヤーの結合**は、文書解像度 1:1 の合成結果を下側ノードへ `ReplaceNode` し、上側を削除します。ビューの拡大や回転は焼き込みません。

**書き出し**は Op ではありません。文書を変更しません。エンジンはビュー変換を掛けない 1:1 の合成結果を RGBA8 で返します。PNG、JPEG、WebP、TIFF への符号化は SDK が行います。画素の上限は読み込みと同じ 64M 画素です。品質パラメータは符号化側に置き、文書へは保存しません。

**スポイト**は、ラスターなら正本タイルの点サンプル、それ以外なら 1:1 合成のその画素です。結果は文書へ書きません。

## 選択、塗り、読みながらの筆

選択の生成（色域、連続領域、拡大、縮小、境界）は R8 の `TileMap` を作り、`SetSelection` で確定します。上限は今と同じ 4096 タイル、投げ縄は 3〜8192 点です。色域と連続領域の計算量にも上限を置き、超えた場合は原子的に拒否します。パスからの選択は、既存のベクターを R8 へラスタライズして同じ Op にします。

単色塗りと線形・円形グラデーションは、対象ラスターと選択の交差を `SetTiles` で 1 回の Transaction にします。グラデーションのパラメータはコマンドの引数であり、ノードには残りません。残るのは画素です。

コピースタンプと指先は、丸ブラシと同じくストローク終了時の読み戻しを `SetTiles` にします。ストローク中の状態（基準点、流量、指先の保持色）は文書に入れません。

- スタンプの読み元はラスターの正本です。常駐に無ければ到達からフォールトします。読み元がラスターでないときは、1:1 合成の派生タイルを読み、書いた結果だけを対象ラスターの正本にします。
- 指先は対象ラスターの近傍だけを読み書きします。
- どちらのツールも、常駐と到達が分かれたあとに足します。未保存の文書では二つの集合が同一なので、保存前でも動作します。

画像チップ、流量、手ぶれ補正は、既存の dab 生成のパラメータとして足します。確定の形は変えません。Undo の深さは `Editor` の `max_undo` をエンジン生成時の値にし、既定 100、上限 1000 とします。

## 互換

| 変更 | format_version | プロトコル |
|---|---|---|
| 常駐の分離、GPU の二口座、ミップ、ライブのバイリニア | 1 のまま | 4 のまま |
| `BlendMode` 全種の描画 | 1 のまま。表示が保存値に揃う | 4 のまま |
| `levels` `curves` `hue_saturation` `invert` を含む文書 | 書き出し時に 2。1 は従来の効果だけ | 5 |
| 切り抜き、回転、反転、画像サイズ | 1 のまま（既存 Op の列） | 5（コマンドを足す） |
| `ReplaceNode`、ラスタライズ、結合、書き出し、スポイト、選択生成、塗り、スタンプ | 描画バージョン 1 のスナップショットは 1。効果を足していなければ 2 にしない | 5 |
| `render_version` 2（整数 4 タップ） | 書き出し時に 3。1 と 2 だけを知るビルドは `Unsupported document format` で拒否する。`render_version` が無い、または 1 の保存は従来どおり（拡張効果が無ければ 1、あれば 2）で、バイト列は変わらない | 5 のまま |
| v1 から v2 への描画バージョン上げ | 明示の編集 1 件（`render.upgrade`）。Undo でバージョン 1 の画素とバイト列に戻る。読み込みと保存では上げない。上げたあとの保存は format 3 | 4 のまま。SDK は `upgradeRenderVersion` |

`format_version` 2 は 1 の上位集合です。2 を読むエンジンは 1 を開きます。1 のエンジンは 2 を `Unsupported document format` で拒否します。描画バージョン 1 で、新しい効果を含まない保存は 1 のまま書き、従来のファイルを開く側を狭めません。

`format_version` 3 は 2 の上位集合で、描画バージョン 2 の保存に使います。3 を読むエンジンは 1 と 2 を開きます。1 または 2 だけを知るエンジンは 3 を `Unsupported document format` で拒否します。`DocumentMeta` は未知フィールドを捨てるので、形式を上げずに `render_version` だけを足すと、古いビルドは同じ文書を f32 経路で描きます。

プロトコル 5 は、SDK と WASM の起動時照合を今のプロトコル 4 と同じ形で行います。不一致は CONFLICT です。

## 実装する順

1. 到達と常駐の分離、パッケージからのフォールト、保存後に版タイルを常駐から外すこと。
2. GPU のフレーム口座とキャッシュ口座。
3. `BlendMode` 全種のシェーダ接続。`Other` の削除。
4. ライブ変形のバイリニアと、正本ハッシュを鍵にするミップ。
5. `Effect` 列挙と、レベル補正、カーブ、色相・彩度、反転。`format_version` 2。
6. 切り抜き、90 度回転、反転、画像サイズ。
7. `ReplaceNode`、ラスタライズ、結合、1:1 書き出しとスポイト。
8. 選択の生成、塗り、グラデーション。
9. スタンプと指先。
10. 残りの効果（シャープ、移動ぼかし、ノイズ、ハイパス、シャドウ、境界線）と、ブラシのチップ、Undo 深さ。

各段は、その段の操作が Undo で戻り、保存して開き直した文書が一致し、GPU を失ったあと正本から同じ画素に戻ることを確認してから次へ進みます。合成とリサンプルは、チャネルあたり 2/255 の既存許容で CPU 参照と比較します。

`gpu-parity` は画素を許容差なしで厳密に比較します（直前の合成・リサンプルが使うチャネルあたり 2/255 の CPU 参照許容とは異なります）。`gpu-parity` のランナー `ubuntu-24.04` が固定するのは OS だけです。Mesa はインストール時に noble-updates から入り、その後も単独で変わり得ます。パッケージ版は意図的にピンしません。古い版はアーカイブから消え、CI が組めなくなります。代わりに、その実行の版を artifact `gpu-parity-report` の `driver.txt` に残します。`gpu-parity` が失敗したときは、まずその `driver.txt` を直近の成功した実行のものと比べます。

## この設計に入れないもの

PSD への往復、CMYK と特色、遠近法とメッシュ変形、液化、被写体選択、生成塗りつぶし、版の分岐とマージ、git 側の編集の取り込み。これらは正本の追加か、別の保存形式か、アフィンを超える幾何です。この文書の操作が動いたあとに別途設計します。
