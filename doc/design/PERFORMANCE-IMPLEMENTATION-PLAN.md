# 縮小表示・復旧高速化 実装計画書

状態: P1–P4とP7の機能・性能検証を実施。実測と未実装項目は[結果報告](../verification/PERFORMANCE-IMPLEMENTATION-RESULTS-2026-10-22.md)を参照。P0の復旧内部計時、P5/P6は未実装。

対象: [設計書](PERFORMANCE-RECOVERY-DESIGN.md)の復旧チェックポイントV2とコールド描画改善。基準は[20層半透明ベンチマーク](../verification/PERFORMANCE-BOTTLENECKS-2026-10-22.md)の B2 395.1 ms、B7 2029.6 ms。目標は B2 ≤250 ms、B7 ≤1500 ms。数値は同一MacのChrome/Metalで確認し、SwiftShaderを使うCIは機能・破損耐性の合否に使う。

## 実施順

```text
P0 計測基盤
  ├─ P1 破損タイルのエラー伝播 ─ P2 復旧V2の生成・読取 ─ P3 OPFS世代選択とSDK接続
  └─ P4 描画の小変更 ─ P5 表示タイルのバッチ化 ─ P6 中断可能な先読み
                                               \              /
                                                P7 統合・配布検証
```

P1はP2の前提。P4以降はP2/P3と独立して進められるが、同じ配布WASMを触るため変更を混ぜずに順次検証する。P5とP6は測定結果に応じて実装範囲を確定する。P7で両経路を同じ20層ベンチマークにかける。

## P0. ボトルネック計測を常設する

**変更**

- `crates/alto-store/src/lib.rs` と `crates/alto-engine/src/lib.rs`: 復旧をZIP読み出し、オブジェクト検証、インストール、追加レコード再生に分けて計時する。
- `crates/alto-raster/src/lib.rs` と `crates/alto-gpu/src/renderer.rs`: CPUキャッシュ命中/欠損、LZ4展開、RGBAコピー、アトラス命中/退避、GPU転送バイト、コマンド構築、`downsample_cached`命中を集計する。GPU timestamp queryは利用可能なアダプターだけで別項目にする。
- `crates/alto-wasm/src/lib.rs`、`packages/alto-sdk/src/worker.js`、`tests/e2e/browser-tests.js`: 診断モード時だけ計測値をJSONに出す。通常のSDK公開契約と文書保存形式には入れない。

**完了条件**: 20層ベンチマークを新規Chromeプロファイルで3回実行し、B2/B7の合計時間と各段階の合計が説明できる。計測を無効にした実行との時間差とメモリ差を記録する。既存の機能テストと画素値が変わらない。

## P1. タイル欠損と破損を区別する

**変更**

- `TileStore::get` の `Option` 返却を `Result<Option<Arc<TileData>>, TileReadError>` 相当へ変更する。`None` は本当に存在しないタイル、`Err` は圧縮形式・展開・内容ハッシュの破損とする。
- `MemoryTileStore` の通常領域とcold領域の両方で同じ検証を通す。`Renderer::upload` と読み出し・保存APIが `CORRUPT_DATA` を呼出元まで伝える。
- 描画失敗後に古い内容を「復旧成功」と通知しない。UIは編集・保存を停止し、利用可能な前世代または緊急退避へ導く。

**テスト**: 圧縮済みタイルのビット反転、欠損、正常な透明タイルを区別するRustテスト。ブラウザで破損を注入し、透明画素として成功扱いされず、保存も成功しないことを確認する。既存のUndo、外部ファイル読込、GPUデバイス喪失テストを再実行する。

**完了条件**: エラーがRust→WASM→Worker→SDK/UIまで途切れない。既存の正常文書の画素・保存バイト列は変わらない。

## P2. 復旧チェックポイントV2の生成・読取

**変更**

- `crates/alto-engine/src/versions.rs` と `crates/alto-store/src/lib.rs`: 同一スナップショットから公開ZIPと復旧専用索引を生成する。索引には各オブジェクトの内容ハッシュ、形式、圧縮長、不透明判定を持たせる。ZIPと索引のSHA-256、サイズ、版をV2エンベロープへ記録する。
- `alto-store` に復旧専用デコーダーを追加する。ZIPのエントリー名、重複、長さ、索引との一致、スナップショット/コミットのハッシュを検査し、タイルは圧縮状態で登録する。外部ZIPを開く既存の `decode_entries` は変更しない。
- `crates/alto-wasm/src/lib.rs` にV2生成・読取APIを追加する。読取は新しい `Engine` に構築し、最後まで成功した場合だけ稼働中の状態と入れ替える。失敗した候補の部分的な文書状態を残さない。
- 旧V1チェックポイントは既存デコーダーで読み、次回チェックポイント時にV2へ移行する。公開 `.alto` と `.altoproj` の形式は変えない。

**テスト**: V2の往復と同一画素、索引の欠損/余分な項目、ZIP内の重複パス、長さ偽装、SHA不一致、古いV1の読取、外部ZIPの従来検証をRustで確認する。内容ハッシュと圧縮バイト列の結び付きは「エンジン作成時の検証」と「保存後の全体ハッシュ」の両方で示す。

**完了条件**: V2復旧で全タイルを先にLZ4展開しない。破損候補は `CORRUPT_DATA` で失敗し、外部ZIPの検証強度は下がらない。

## P3. OPFSの世代選択とSDKの復旧を接続する

**変更**

- `packages/alto-sdk/src/storage-core.js`: `journal-a.bin`/`journal-b.bin` の候補を検証終了まで保持する。最新のCRC・V2 SHA・索引検査が失敗したら旧世代へ進み、採用後にだけアクティブ世代を決める。候補選択前に旧ジャーナルを切り詰めたり上書きしたりしない。レコード長とパッケージ長の上限を整合させる。
- `packages/alto-sdk/src/worker.js`: V2なら復旧専用WASM API、V1なら既存 `openPackage` を呼ぶ。追加レコードの順序と、不完全な末尾の警告を維持する。
- `packages/alto-sdk/src/index.ts`: `recovered` は文書と記録の復元が確定してから通知する。どの世代から戻ったか、切り捨てがあったかを結果に含める。利用者の編集を再開する前に保存状態を照合する。

**テスト**: `storage-session.test.js` に世代選択・flush途中終了・CRC/SHA不一致を追加。`tests/e2e/browser-tests.js` で実際のOPFSとWorker再起動を通し、V1移行、最新世代破損時の前世代復帰、両世代失敗、追加レコードの一度だけの再生、保存障害後のUIを確認する。

**判断点**: B7を同じ20層条件で再計測する。`openPackage`相当の時間とB7合計を記録する。目標を満たしてもP4以降の描画側の仕事量は独立に評価する。

## P4. 描画の小変更を個別に測る

**候補を一変更ずつ適用**

1. `crates/alto-gpu/src/renderer.rs` の `rgba_pixels` で、RGBAは元の画素スライスを `queue.write_texture` へ渡し、R8だけ展開する。
2. `commands` が各表示タイルで全レイヤーの `BTreeMap` を作り直す箇所を、シーン更新時の索引と範囲問い合わせへ置き換える。ストロークプレビューの上書きも維持する。
3. 必要ならアトラスの空き検索/退避候補の選択を索引化する。P0でこの処理が有意な場合だけ着手する。

**完了条件**: 各変更前後のB2/B7、転送バイト数、CPU時間を保存する。半透明境界、キャンバス端、マスク、ブレンド、ズーム、Undoで画素が一致する。B3のペン入力遅延とメモリが悪化しない。効果が測れない変更は元へ戻す。

## P5. 可視表示タイルをアトラス容量内でバッチ化する

**変更**

- `Renderer::render` が不足している表示タイルを列挙し、中央優先で必要な入力タイルの固有ハッシュを集計する。アトラス512スロットと表示キャッシュ256スロットを守るようバッチを区切る。
- バッチ内では入力タイルの取得/転送を共有し、複数の表示タイルの合成コマンドを提出する。参照中のスロットを固定し、GPUキューの読取と次の上書きの順序を明示する。
- 効果・テキスト等が通る `compose_m5`、1タイルで容量を超える場面、GPUデバイス喪失では従来経路を使えるようにする。

**テスト**: バッチ境界をまたぐ半透明20層、アトラス退避、効果/マスク/文字、キャンバス端、表示スロット上限、GPU喪失の画素比較。バッチサイズを変えたB2/B7とアトラス再転送回数を記録する。

**判断点**: B2 ≤250 msを複数ランで満たし、B3が維持されればP6は体感改善として別に扱える。未達ならP0の内訳から次の段階を選ぶ。

## P6. 入力を妨げない先読みと中断可能なジョブ

P0/P5の結果で、縮小段階のキャッシュ不足または1タイルの長い同期処理が残る場合に着手する。

- `compose` を計画、タイル準備、コマンド作成、提出に分け、入力準備中にWorkerへ制御を返せるようにする。提出済みGPUジョブは取り消さず、古い結果を表示キャッシュへ採用しない。
- 可視・入力関連の仕事を先に実行し、操作が落ち着いている間だけ次の縮小段階を既存の表示256スロット内で先読みする。`invalidate(bounds)` とジョブ世代を結び、無関係な有効キャッシュは残す。
- `downsample_cached` の利用率、先読みで増えた電力/CPU時間、ペン入力のp95を測る。可視タイルを先読みで退避させない。

**完了条件**: ズーム連打と編集の競合で古い画素が出ず、B1/B3とメモリ上限を維持する。B2/B7の完全描画を短縮したかを別に記録し、早期プレビューの時刻を成功判定に混ぜない。

## P7. 統合、CI、配布検証

**必須ゲート**

- `sh scripts/check.sh`: Rust整形、テスト、native/wasm32 Clippy、ピン留めしたリリースWASMを組み直して `wasm/SHA256SUMS` と照合、SDKビルド、Storage Sessionテスト、ビルドメタデータ。
- リリース時に一度 aarch64-apple-darwin で `sh scripts/update-wasm-sums.sh` を実行し、`wasm/SHA256SUMS` と `verification/build.json` を更新する。WASMバイナリはコミットしない。リポジトリ全体の `SHA256SUMS` は置かない。
- `ALTO_BROWSER_GPU=swiftshader ALTO_BROWSER_REPORT_DIR=<出力先> node scripts/verify-browser.mjs --functional`: 既存M4〜M8機能と追加したOPFS/破損テスト。GitHub Actionsの現行CIに載せ、保存されたJSONの失敗0件を確認する。
- 同じMacのChrome/Metalで `ALTO_BROWSER_REPORT_DIR=<出力先> node scripts/verify-browser.mjs` を新規プロファイルから複数回実行する。B2 ≤250 ms、B7 ≤1500 ms、B3 p95 ≤33.4 ms、GPU推定 ≤512 MiB、WASM ≤1024 MiBを確認し、生JSONを保存する。性能値はCIのSwiftShader実行だけで合格としない。
- 旧版V1ジャーナル、保存中断、破損、前世代への復帰、外部 `.alto` 読込、実際の編集・保存・再起動を一連の操作として確認する。

**完了条件**: ソース、両配布WASM、SDKビルド、ビルドメタデータ、チェックサム、実ブラウザの結果が同じ変更を示す。設計書の性能目標を満たした測定JSONと、未達の環境・条件を `doc/verification/RESULTS.md` に記録する。

## 停止・見直し条件

- P3後も `openPackage` 相当の時間が大きく残る場合は、ZIP構造検査、SHA計算、スナップショット/コミット復元を再分解してから次の最適化を決める。
- P4後にアトラス転送よりGPU実行が支配的と判明した場合は、P5のバッチ規模を縮め、GPUシェーダー計測と合成アルゴリズムを先に検討する。
- 画素差、破損見逃し、B3入力遅延、メモリ超過が出た変更は、その段階で戻して原因を特定する。性能目標だけで正しさを上書きしない。

この計画では、P0〜P3で復旧の約800 ms、P4〜P6で縮小・コールド描画の負荷をそれぞれ減らす。各段階の測定結果を次の段階の判断材料にする。

CI: PR の `wasm-fast` はキャッシュを使い、`wasm/SHA256SUMS` と build.json の差分を summary / `wasm-hashes` artifact に報告するだけ。main / tag push の `wasm-release-hashes` はクリーンな arm64 macOS ビルドで全不一致を表示して失敗する。これらはリリースバイナリの値で、v1/v2 render hash 検査は変更しない。
