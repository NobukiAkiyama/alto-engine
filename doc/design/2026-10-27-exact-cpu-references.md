# 5 つの parity xfail を画素一致の CPU 参照にする

作成日：2026-10-27

状態：方針。`color-adjust` は同じ日付の実装で通常の parity ケースにした。`mask`、`gaussian-blur`、`vector-fill`、`text` はこの方針に沿って、それぞれ main から分岐した別の PR で実装する。

関連：[画像編集](IMAGE-EDITING.md)。`gpu-parity` が許容差なしの画素一致であることは、そちらの「実装する順」の末尾に既にある。この文書では繰り返さない。

## 共通

対象はブラウザ組の `mask`、`gaussian-blur`、`color-adjust`、`vector-fill`、`text` である。いずれも `composite.wgsl` の外で、中間は RGBA16F、最後は `effects-resolve.wgsl` が RGBA8 unorm へ書く。

CPU 参照は Rust（`crates/alto-gpu/src/cpu_composite.rs`、テストだけ）と JS（`tests/e2e/cpu-composite.js`）の両方に置く。lavapipe と Metal は Rust 参照とヘッドレスのシェーダ実行を比較する。SwiftShader のブラウザ組は JS 参照と本番の `readTile` を比較する。

既存の記録は変えない。

- `tests/parity/render-v1.txt` は描画バージョン 1 の合成ケースのまま再生成しない。
- `tests/parity/cpu-reference.txt` の既存行は描画バージョン 2 の整数 4 タップのまま再生成しない。新しいケースをロックするときは行を足すだけで、既存の名前とハッシュは動かさない。
- 描画バージョン 1 と 2 のシェーダ出力は変えない。シェーダを変えるとその出力が変わる場合は、編集の前に止めて報告する。ビットを揃える式が今の出力と違うときは、新しい描画バージョンの分岐にだけ置き、1 と 2 の文は残す。

f16 のストアと RGBA8 unorm のストアは、どちらも半整数を偶数側へ丸める。f16 は f32 の部分集合なので、ロードは厳密である。

## color-adjust

調整レイヤーは、下の合成結果を `effects.wgsl` の `info.x == 3` で置き換える。parity の画像は不透明な一色で、変形は恒等、パラメータは明度 0.6、コントラスト 1、彩度 1 である。

通る段は次のとおり。

1. モード 0。アトラスの unorm8 を `byte/255` の f32 で読み、`rgb * a` をプレマルチプライして f16 へ書く。
2. 透明な f16 への通常合成（モード 1）。`blend.wgsl` の `blend` を f32 で評価し、結果を f16 へ書く。
3. モード 3。直線色は `rgb / max(a, 0.000001)`、その後 `(rgb - 0.5) * contrast + 0.5 + brightness`、輝度は `dot(rgb, vec3(0.2126, 0.7152, 0.0722))`、`mix(l, rgb, saturation)`、`clamp` してから `a` を掛け、f16 へ書く。
4. resolve が f16 を RGBA8 unorm へ量子化する。

CPU はこの順を、左結合の f32（積和は融合しない）と段の間の f16 往復で評価する。コントラストと彩度がちょうど 1 のとき、`mix` は恒等で、`(rgb - 0.5) * 1 + 0.5` は分離した減算と加算と同じビットになる。シェーダは編集しない。描画バージョン 2 の画素も、ロック済みハッシュも、そのままである。

あるバックエンドだけこの f32 列からずれた場合は、バージョン 2 の式を書き換えない。整数化した式は新しい描画バージョンにだけ置き、報告してからその分岐を足す。

## mask

レイヤーの f16 画像に、モード 4 が `load_a(p) * coverage * opacity` を掛ける。選択マスクは R8 で、アトラスへ入れるとき R=G=B=カバレッジ、A=255 に広げる。サンプルは `sparse` の最近傍で、カバレッジは `.r` である。矩形選択は画素境界に揃うので、カバレッジは 0 か 1 である。

CPU は color-adjust と同じモード 0 と透明への通常合成のあと、モード 4 と f16 ストア、unorm resolve を評価する。0 と 1 の乗算は厳密なので、シェーダは編集しない。

## gaussian-blur

モード 2 は水平と垂直の 2 パスである。半径は `ceil(radius / scale)`、シグマは `max(radius / scale / 3, 0.333333)`、重みは `exp(-i*i / (2*sigma*sigma))` で、寄与を足して重みの和で割る。`exp` は Metal、lavapipe、SwiftShader でビットが揃わない。CPU が同じ libm を呼んでも、3 つの GPU が互いに一致するとは限らない。

ビットを揃える参照は、重みを CPU で一度だけ Q16 の表にし、GPU はその表を整数で積和する。f16 へ書く値は、その整数から一意に決まるビットパターンにする。これは今の `exp` の画素と違うので、描画バージョン 2 の文は残し、新しい描画バージョンだけが表を使う。ぼかしはロック済みハッシュに含まれない。バージョン 2 の文書の画素は残る。

バージョン 2 の算術を書き換える以外に分岐を入れられないときは、そのシェーダ編集の前に止めて報告する。

## vector-fill

塗りは Lyon のメッシュを 4x MSAA の R8 へ描き、ハードウェアの resolve のあと RGBA16F へ塗る。サンプル位置は Metal、Vulkan、SwiftShader で同じではない。ハードウェアのラスタライザを残したまま、CPU 側の「4 サンプル」を 3 つの GPU に同時に一致させることはできない。

ビットが揃う参照は、画素内のサンプル位置を固定した被覆計算である。覆ったサンプル数は整数で、カバレッジは `n/4` としてから今の塗りと f16、unorm resolve に渡す。これは今の MSAA とは別のラスタライザなので、描画バージョン 2 は今のパイプラインのままにする。parity のケースは新しい描画バージョンでその被覆を CPU と GPU の両方に使う。合成だけのロック済みハッシュにベクターは含まれない。

描画バージョン 2 の MSAA パス自体を書き換える必要が出たときは、編集の前に止めて報告する。

## text

xfail のサイズ 72 は `ATLAS_MAX_EM_PX`（24）以上なので、今はベクターのメッシュへ落ちる。その画素は vector-fill の決定的な被覆が揃ったときに一致する。

24px 未満は別経路で、既に CPU の `glyph_atlas::rasterize` が被覆を作り、`glyph-atlas.wgsl` が `floor(position)` と `textureLoad` で 1:1 に写す。parity の text はこの経路にする。サイズは 24 未満、CPU 参照は同じ `rasterize` と、ブリットの式（カバレッジは `byte/255`、色を掛けてプレマルチプライ、f16 へ書き、透明へ通常合成、unorm resolve）である。シェーダは編集しない。大きいグリフは vector-fill の新しい描画バージョンに従う。
