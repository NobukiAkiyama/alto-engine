# 5 つの parity xfail を画素一致の CPU 参照にする

作成日：2026-10-27

状態：方針。実装順は `color-adjust`、`mask`、`vector-fill`、`gaussian-blur`、`text`。各パスは main から切った別 PR で、main へ向ける。`color-adjust` は最初の PR で通常の parity ケースにした。

関連：[画像編集](IMAGE-EDITING.md)。

記録してあるハッシュは動かさない。`tests/parity/render-v1.txt` の全行と、`tests/parity/cpu-reference.txt` の既存行は再生成しない。新しいケースを足すときは行の追加だけにする。

描画バージョン 1 と 2 の画素は変えない。バージョン 3 の式は `render_version` が 3 の文書だけが使う。バージョン 1 と 2 の式はコードに残す。バージョン 3 を既定の新規文書にする変更は、ロック済み合成ケースの画素がバージョン 2 と一致することを確認してからにする。一致しないあいだ、parity の新ケースだけがバージョン 3 を名指しで使う。バージョン 3 の文書を保存すると `format_version` は 4 になる。4 を知らないビルドはファイルを拒否する。`DocumentMeta::validate` が受け付ける `render_version` は 1、2、3 だけである。それ以外は拒否する。未知の値を読み飛ばして古い式で描くことはしない。

CPU 参照は Rust（`crates/alto-gpu/src/cpu_composite.rs`、テストのみ）と JS（`tests/e2e/cpu-composite.js`）に同じ式で置く。WGSL はその式を実行する。段と段のあいだの RGBA16F ストアと、最後の RGBA8 unorm ストアは、どちらも半整数を偶数側へ丸める。

## color-adjust

1. 今日ずれる箇所。モード 3 は `rgb / max(a, 0.000001)`、`(rgb - 0.5) * contrast + 0.5 + brightness`、`dot`、`mix` である。WGSL が正しい丸めを保証するのは加減乗だけである。f32 の除算は最大 2.5 ULP ずれてよい。コントラストが 1 でない積和と、彩度が 1 でない `mix` は融合し得る。`exp` や `sin` はない。f16 ストアと unorm ストアの丸めは仕様で一意である。

   parity の入力は 256×256 の勾配である。R は x、G は y、B は `(x * 3 + y * 5) & 255` で、各行が青の 0..255 を踏む。アルファは y=0 で 0、y=1 で 1、y=2 で 128、y=3 で 254、それ以外の行は x である。R、G、B、アルファはそれぞれ 0..255 を含む。設定はコントラスト {0.5, 1.7}、彩度 {0, 0.35, 1.6}、明度 {−0.35, 0.45} の直積（12 通り）で、文書と同じ `f64 as f32` である。全画素を比べる。不透明色に明度だけ足すケースは、除算と `mix` とコントラストの積が恒等になるので使わない。

   lavapipe（LLVM 20.1.2）でモード 3 の f32 式をこの 12 通りと比べると、全部の設定で画素が違った。最初の違いは `c=0.5 s=0 b=-0.35` の画素 (251, 2) である。ソースは `[251, 2, 251, 128]`。GPU は `5,5,5,128`、CPU の f32 式は `6,6,6,128` だった。モード 0 の `v.rgb * v.a` を f16 に書く段も、同じ勾配の (80, 2) で青が 1 違う（GPU `40,1,125,128`、CPU `40,1,126,128`、ソースの B は 250、アルファは 128）。入力の f16 が既に実装依存なので、その上に整数式を載せても揃わない。

2. CPU、WGSL、JS で同じ整数式。描画バージョン 3 だけが使う。モード 18 はアトラスの unorm を `u32(clamp(v, 0, 1) * 255 + 0.5)` でバイトに戻す。プレマルチプライは `(c * a * 16384 + 32512) / 65025`、ストレートのアルファは `(a * 16384 + 127) / 255`。どちらも整数除算で、1.0 は 16384（Q14）である。その整数から f16 ビットを一意に作って書く。モード 19 は、宛先が正確な 0 でブレンドが normal のとき、その f16 をそのままコピーする。それ以外のブレンドはバージョン 2 のモード 1 に戻る。モード 17 は載っている f16 を Q14 へ切り捨ててから、明度・コントラスト・彩度も同じ Q14 へ量子化する。範囲は −1..4、16384 倍、半整数は 0 から遠い側へ丸める。アルファが 0 のストレート RGB は 0。それ以外は `(q << 14) / alpha` を 0..16384 に切る。`(straight - 8192) * contrast` を 16384 で割り（0 から遠い側へ丸める）、8192 と明度を足し、−32768..32767 に切る。輝度の重みは 3483、11718、1183 で、和は 16384 である。彩度の mix も同じ整数除算で、0..16384 に切ってからアルファを掛け、16384 で割る。結果の Q14 から f16 を一意に作り、アルファの f16 ビットは入力のまま残す。最後の unorm8 は偶数丸め。モード 0、1、3 の f32 の文はバージョン 1 と 2 のために残す。バージョン 3 のラスタサンプルと、透明な背面への normal ブレンドはモード 18 と 19 になる。それ以外のエフェクトの式は、それぞれの PR まで今のままである。

   unorm からバイトを戻す段は、変換の誤差が半バイト（約 0.002）より小さければ同じバイトになる。WGSL の f32 除算が最大 2.5 ULP ずれても、その誤差は半バイトよりずっと小さい。バイトを戻したあとの加減乗除は整数で、仕様で一意である。3 実装が全画素一致しても、それは Metal、lavapipe、SwiftShader についての観測であり、仕様があらゆる実装の unorm 変換をその範囲に収めるとは書いていない。

3. 既存出力は変えない。バージョン 1 と 2 の式と、`tests/parity/render-v1.txt` および `tests/parity/cpu-reference.txt` の記録済みハッシュは触らない。新規文書の `render_version` は 2 のままである。バージョン 3 の文書を保存すると `format_version` は 4 になる。`validate` が受け付ける `render_version` は 1、2、3 だけで、それ以外は拒否する。1 から 2 への更新は今のままである。3 へ自動では上がらない。

   parity はこの勾配と 12 通りを、native（macOS Metal）、gpu-parity（Ubuntu lavapipe）、wasm（macOS の Chrome for Testing、`ALTO_BROWSER_GPU=swiftshader`、`node scripts/verify-browser.mjs --functional`。アダプタの architecture に `swiftshader` が含まれること）で全画素比べる。SwiftShader がこのケースを実行するのは wasm ジョブの parity スイートである。ブラウザは `tests/fixtures/render-v3-empty.alto` を開く。`createDocument` はバージョン 2 のままで、wasm にバージョンを書くメソッドは足していない。lavapipe では 12 通りとも整数式と全画素一致した。Metal と SwiftShader の結果は、この PR の native と wasm の CI が記録する。

## mask

1. 今日ずれる箇所。モード 4 は `load_a * coverage * opacity` である。カバレッジは R8 をアトラス上で R=G=B=値、A=255 にした最近傍サンプルの `.r` で、`byte/255` の f32 になる。矩形選択は画素境界に揃い、値は 0 か 255 だけである。0 と 1 の乗算は厳密なので、このケースのずれはカバレッジ側にはない。入力の色は color-adjust と同じ f16 往復を通る。ぼかし縁（feather）を掛けたマスクは別で、ガウス重みの `exp` がずれる。parity の矩形には feather はない。

2. CPU、WGSL、JS で同じ式。カバレッジバイトが 0 なら出力は 0、255 なら入力の f16 色をそのまま返す。opacity が 1 でないときは、色の f16 値を Q8（0..255）に偶数丸めで戻し、`（色 * opacity_q8 * coverage + 127）/ 255` の整数除算で書き、再び f16 へ一意に載せる。parity の矩形は coverage が 0 か 255 で opacity が 1 なので、整数除算は恒等になる。

3. 既存出力は変えない。バージョン 2 のモード 4 の文は残す。描画バージョン 3 は要らない。

## vector-fill

1. 今日ずれる箇所。塗りは Lyon のメッシュを 4x MSAA の R8 へハードウェア描画し、実装依存の resolve でカバレッジにする。サンプル位置は Metal、lavapipe、SwiftShader で同じではない。`vector.wgsl` の被覆フラグメントは常に 1 を返し、ずれはラスタライザ側にある。その後の `vector-paint.wgsl` は `coverage * color` を f32 でプレマルチプライして RGBA16F へ書く。

2. CPU、WGSL、JS で同じ式。画素を 16×16 の整数格子とみなし、4 つのサンプル位置を Q4 の固定オフセット（画素原点から `(4,4)`、`(12,4)`、`(4,12)`、`(12,12)`、単位は 1/16 画素）に固定する。辺の内外はメッシュの整数化座標（頂点は Q8）で判定し、覆った個数 `k`（0..4）からカバレッジバイトを `(k * 255 + 2) / 4` とする。塗りは `色 * そのバイト / 255` を整数で行い、f16 ビットをその整数から一意に作る。ハードウェア MSAA は使わない。

3. この式は今の MSAA の画素と違う。描画バージョン 3 の文書だけが使う。バージョン 1 と 2 は今の 4x MSAA のままなので、記録済みハッシュは動かない。合成だけのロック済みケースにベクターは含まれない。

## gaussian-blur

1. 今日ずれる箇所。モード 2 は水平と垂直の 2 パスで、半径 `ceil(radius / scale)`、シグマ `max(radius / scale / 3, 0.333333)`、重み `exp(-i*i / (2*sigma*sigma))` である。`exp` は Metal、lavapipe、SwiftShader でビットが揃わない。CPU の libm をコピーしても 3 つの GPU には同時に一致しない。

2. CPU、WGSL、JS で同じ式。オフセット `i` は整数。重みは Q16 で、`exp` はライブラリ関数を呼ばず、指定した次数の整数多項式（係数は Q16 の定数）で評価する。正規化は重み和による整数除算で、余りは切り捨てる。結果の Q16 値から f16 ビットを一意に作る。WGSL は同じ係数と同じ整数演算を使う。

3. この式は今の `exp` の画素と違う。描画バージョン 3 だけが使う。バージョン 2 の `exp` の文は残す。ぼかしは記録済みハッシュに含まれない。

## text

ビット一致はできる。サイズを下げてメッシュ経路を避ける、ということはしない。

1. 今日ずれる箇所は二つある。parity の "Ag" は 72px で、`ATLAS_MAX_EM_PX`（24）以上なので vector-fill と同じ 4x MSAA へ落ちる。ずれはそこのサンプル位置である。24px 未満は `glyph_atlas::rasterize` が f32 の符号付き面積を走査順に足し、`(|acc| を 1 で切った値) * 255 + 0.5` を u8 へ切り捨てる。この走行和が Rust の f32 と JS の f64 でずれる。GPU 側の `glyph-atlas.wgsl` は `floor(position)` と `textureLoad` の 1:1 コピーで、こちらは整数のままずれない。

2. CPU、WGSL、JS で同じ式。72px の parity は vector-fill の Q4 サンプルと Q8 頂点をそのまま使う。24px 未満のアトラスは、面積を Q16 の固定小数で足す。量子化は `min(|acc|, 65536) * 255 / 65536` の整数除算とする。ブリットのシェーダは変えない。

3. どちらの整数式も今の画素と違う。描画バージョン 3 だけが使う。バージョン 2 は今の MSAA と今の f32 ラスタライザのままなので、記録済みハッシュは動かない。text をビット一致にできない、という結論にはしない。
